# Ben Eater 6502 Code

This directory keeps the code stages for the 6502 breadboard build, split into three groups:

- `machine_code/` - hand-written opcodes and the ROM image built from them, before the assembler is introduced.
- `assembly/` - 6502 assembly source, assembled with `vasm6502_oldstyle`.
- `debug/` - Arduino sketches used to observe the buses and control signals on the breadboard.

Filenames describe what each file does, while this table preserves the Ben Eater video stage and original source link.

## `machine_code/`

| File | Purpose | Source video | Original link |
| --- | --- | --- | --- |
| `dancing_led_assembly.py` | Generates the first hand-written machine-code ROM image. | Part 2: How do CPUs read machine code? | https://eater.net/downloads/makerom.py |
| `led_test_rom.bin` | 32K ROM image generated by `dancing_led_assembly.py`. | Part 2: How do CPUs read machine code? | https://eater.net/downloads/makerom.py |

Regenerate the image with:

```bash
python3 code/machine_code/dancing_led_assembly.py
```

## `assembly/`

| File | Purpose | Source video | Original link |
| --- | --- | --- | --- |
| [`../program1.s`](program1.s) | First pass at the rotating LED pattern, stored directly in `code/`. | Part 3: Assembly language vs. machine code | Local first draft |
| [`via_led_rotate.s`](assembly/via_led_rotate.s) | Original LED rotation program; writes to VIA `PORTB` at `$6000` and `DDRB` at `$6002`. | Part 3: Assembly language vs. machine code | https://eater.net/downloads/blink.s |
| `hello_world_long_version.s` | Prints to the LCD with inline enable pulses. Needs no RAM. | Part 4: Connecting an LCD to our computer | https://eater.net/downloads/hello-world.s |
| `hello_world_short_version.s` | Prints to the LCD using subroutines, the stack, and LCD busy-flag polling. Needs working RAM. | Early-series final hello-world assembly with stack/subroutines | https://eater.net/downloads/hello-world-final.s |

Parts 5 through 7 do not have separate source-file links on the project page or in their video descriptions. The linked final hello-world assembly is included as `hello_world_short_version.s` because it covers the stack/subroutine version used in that part of the series.
